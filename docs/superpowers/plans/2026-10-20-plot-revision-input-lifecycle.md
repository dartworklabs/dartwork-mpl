# Plot Revision Input Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover a plot after its original input disappears, using explicitly authorized independent copies and an honest Copy/Retained receipt.
**Architecture:** Extend the existing artifacts capability with pure revision values, descriptor-authorized input storage, bounded owned workers and one drained server lifecycle. Delivery coordinates input and bundle commits; execution receives only an opt-in read-only mapping. Preserve native matplotlib Figure/Axes.
**Tech Stack:** Python ≥3.10, stdlib, existing matplotlib/FastMCP ≥2.13.3,<4, pytest; local execution Python 3.12; no new dependencies.
**Spec:** Read [lifecycle](../specs/2026-10-20-plot-revision-input-lifecycle-design.md), [freshness](../specs/2026-10-20-plot-revision-input-freshness-design.md), and [ADR 0004](../../adr/0004-retained-input-revision-contract.md) before execution. The recorded “좋아 진행해” covers the explained lifecycle and bounded freeze exception; do not ask for that approval again. Real operator grants remain absent.

## Global Constraints

- Preserve artifact v1's five members, six manifest keys, combined 32 MiB, exactly seven-day retention, existing error enum and render/get envelopes; `revision=None` preserves controlled-result legacy serialization/log bytes and injects nothing.
- Append only `delete_plot_inputs(artifact_id: str)`; full live inventory becomes **19/10/9/2**, preserving every existing identity and relative order. Keep historical baseline/color digests unchanged; extend the explicit historical projection by this tool only.
- Revision: closed v1, parent or nonempty inputs, ≤16 KiB/depth ≤4; ≤8 unique names; identifiers `[A-Za-z0-9_-]{1,64}`, lowercase UUID4hex/SHA-256; relative POSIX path UTF-8 ≤1024 bytes, no empty/`.`/`..`/backslash/NUL/absolute components; reject unknown fields/types without normalization.
- Policy: only `DARTWORK_MPL_INPUT_POLICY`, startup-only closed `{schema_version:1,storage_dir,copy_roots}` JSON ≤16 KiB, duplicate keys rejected. Unset denies copy/reuse/delete; parent-only revision needs no input grant. Invalid policy/unsupported descriptor or lock operations disable retention with configuration_error while legacy paths keep working.
- Principal is the local server OS operator. Policy file is no-follow regular, operator-owned, not group/other writable; all canonical non-symlink ancestors are root/operator-owned and not group/other writable. Reject macOS alias paths. Storage is 0700/files 0600, operator-provided same-host local filesystem outside datasets; reject storage overlap with artifact root or any copy root, allow copy-root overlap. Do not deploy any actual policy.
- Startup pins root FDs; each call duplicates them. Reject replaced roots; descriptor-walk descendants with `O_NOFOLLOW`, directory intermediates, final `O_NONBLOCK|O_NOCTTY` plus regular-file fstat. Store-owned files retain owner/mode/single-link/object checks. No path-string authority or unsafe OS fallback.
- Copy at most **8 files ×8 MiB**, **32 MiB payload/request**, **64 KiB chunks**; stream size/hash limits. Store **512 MiB/128 sets** counts metadata, pending/reserved and revoked residue, with no live eviction/overrides. Reserve request maximum plus bounded metadata/marker allowance before execution.
- Owned copy/post-check worker phases have **10s/5s** deadlines; copy plus post-check data reads ≤**65 MiB** including overrun detection, retained verification is one copy/hash pass. Reap workers before releasing stages/reservations. No universal wall-clock or OS sandbox guarantee.
- Serial retention render/delete/maintenance; one same-host startup lock, second server retention refused; no cross-host exclusion claim. Admission stops before drain, workers/calls finish or are reclaimed before FDs/lock close; maintenance startup/every operation/**60s** after active work.
- Private sets use `.pending-<UUID4hex>/` then `<UUID4hex>/`, `000.bin`–`007.bin`, `inputs.json` ≤16 KiB, `.revoked`; no original basename/path. Same child ID/UTC clock instant and +7 days for bundle/input set; each retained child owns independent bytes. Reads never renew; admitted live inputs/parent stay pinned through expiry; no cascade.
- Delete all six spec states without requiring valid/live metadata or bundle: marker atomic-create→file fsync→set fsync→payload unlink→metadata unlink→set fsync→marker unlink→rmdir→root fsync. Absent also requires safe absence/root fsync. Unsafe/unknown residue stays counted and returns publication_error; marker persistence failure removes no payload and guarantees denial only in this process.
- Startup removes only positively owned pending namespaces or verified expired sets through the common deletion protocol. Missing/changed artifact root, HOME or damaged bundle never proves committed inputs unpublished; preserve/count them and allow original-root restoration before expiry. No persistent root binding; no recursive cleanup.
- Commit observer is read-only manifest-only, ≤**512 KiB** plus overrun detection, matching ID/times; no root creation, cleanup or `load()`. After artifact-stage exit, roll back only this call's proven unpublished set; ambiguous commit stays counted. Ready requires both commits.
- Provenance v1 stores pinned parent manifest/source digests, copied name/hash/size/child locator, closed `selection={kind:"copy"}` or `{kind:"retained",artifact_id,input_name}`, `evidence:"copied_and_boundary_checked"`, `reproducibility:"not_claimed"`. Only successful revision has provenance; metadata has no receipt. Receipt is immutable creation-time evidence, never current availability: delete/expiry may leave the report accessible, and actual Retained admission rechecks grant/expiry/commit. No live-status API or capture/as-of/latest claims; child time is publication time.
- Read-only `dartwork_inputs` is injected only for input-bearing execution via private stdin/FD channel, never argv/environment; keep exact submitted source, cwd/environment and existing timeout behavior. Existing source/log/traceback/automatic exc_msg may expose paths; new receipt/errors/locators must not add policy paths/basenames.
- No DB, dependencies, watcher, upstream synchronization, listing, idempotency key, source rewriting, discovery filtering, arbitrary-Python semantic proof, secure erase/backups or power-loss guarantee. Lost responses/offline expiry can leave counted bytes; document it.

## Review Focus

- Failing copy/root replacement must never read an outside sentinel or silently reuse an old snapshot (Tasks 3, 7).
- Close during blocked copy and overlapping client sessions must preserve ownership until worker reap; a second server cannot obtain the lock early (Tasks 3, 6).
- Root/HOME changes and artifact fsync/cleanup ambiguity must not delete committed bytes; restoration must recover them (Tasks 2, 4, 5, 7).
- Corrupt/metadata-less/revoked/unknown residue and failed durability barriers must never report deletion success or free capacity prematurely (Task 4).
- Mixed selections, changed CSV, renamed/missing inputs and unknown provenance must produce honest receipts/comparison guidance without freshness inference (Tasks 1, 7, 8).
