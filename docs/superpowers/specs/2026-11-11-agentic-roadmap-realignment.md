## 설계

### 1. 정상 코퍼스 검사 (일반형)

- **코퍼스.** `docs/examples_source/**/*.py` 와 동봉 템플릿(basic 18, tier-2 18).
- **분류.** WARNING 이상인 지적마다 렌더한 그림을 보고 TRUE(독자가 결함을 본다), FALSE(검사가 틀렸다),
  INTENDED(측정은 맞지만 예제가 의도했다)로 나눈다.
- **수리.** FALSE 는 검사를 고친다. TRUE 는 예제를 고치되 외형이 바뀌면 전후 PoC 를 거친다. INTENDED 는
  스크립트별 면제 목록에 사유와 함께 적는다. 경고를 지우려고 임계값을 일괄로 올리지 않는다.
- **INFO.** 나열을 한정한다(쌍 수천 개 대신 요약과 개수). 원본 findings 는 보존한다.
- **고정.** 코퍼스를 실행해 WARNING 이 0(면제 제외)인지 보는 시험을 CI 에 둔다. 면제 목록은 늘어날 때 리뷰에서 보인다.

### 2. 에이전트 스모크 (탐색형)

- **목적.** 통계 판정이 아니라 실패 수집이다. 스킬을 설치한 임시 프로젝트에서 `claude -p` 와 `codex exec` 가
  자연어 요청으로 그림을 만들고 고치는 것을 돌려, PNG 와 기록에서 결함을 찾는다.
- **범위.** 새 문항 8–12개를 호스트당 한 번. 기준선이 실패할 만한 것으로 짠다 — 다중 패널, 긴 한글 라벨,
  twin 축, 날짜 축, "여기만 고쳐" 편집. 기존 문항은행·held-out·원본 400건은 열지도 바꾸지도 않는다.
  문항과 러너는 `evals/smoke/` 에 따로 둔다. 기존 `evals/agentic/run.py` 는 `load_cases` 가 문항은행 전체를
  읽으므로 쓰지 않는다. 호스트를 띄우고 격리하는 방식만 참고하고, `evals/agentic` 은 가져오지도 고치지도 않는다.
- **종료 조건.** 한 회차가 끝나면 멈춘다. 결과는 (a) 결함 목록, (b) 검증기가 잡았는지 여부, (c) 토큰·턴 수다.
  결함마다 이슈 하나 또는 "고치지 않음"과 사유를 남긴다. 회차를 늘려 유의성을 찾지 않는다.
- **사후 기록.** 회차가 끝나면 이 문서 아래에 결과 요약과 다음 회차 여부를 적는다.

### 3. 실패 주도 수리

코퍼스 검사와 스모크가 낸 항목을 고친다. 수리마다 재현 실패 → 수정 후 통과를 PR 에 남긴다.
