## 결정

- **주 사용자**는 Claude Code·Codex 같은 코딩 에이전트를 쓰는 사람이다. 이들은 그림을 자연어로 요청하고 자연어로 고친다.
- **우선순위**: 외관 개선보다 에이전트 워크플로 적합화가 먼저다.
  - 기존 style(폰트·굵기·스파인·프리셋 외관)은 바꾸지 않는다.
  - scientific의 왼쪽 스파인은 유지한다.
- **동결**: MCP 결과물 보존·리비전·입력 보관·삭제·데이터 수리의 신규 기능을 멈춘다.
  - 코드를 지우지는 않는다.
  - 기존 도구와 계약, ADR 0003·0004의 잠금은 유지한다.
  - 보안 버그와 데이터 손실 버그는 계속 고친다.
- **보류**: #484(홈페이지·계정·커뮤니티·호스팅)와 #485(docs 분리). 0–3단계의 지표가 기준선보다 나아진 뒤에 다시 판단한다.
- **#483 범위 변경**: #483의 "새 공개 loader/CLI를 채택하지 않는다"는 범위 제한을 이 결정으로 바꾼다.
  - skill 설치 명령과 `dm.review`를 추가한다.
  - 기존 공개 이름과 `asset/**` 경로(ADR 0005 동결선)는 그대로 둔다.

## 북극성과 원칙

목표는 dartwork-mpl을 처음 보는 프로젝트에서도 Claude Code·Codex가 다음 세 가지를 해내는 것이다.

1. 처음부터 올바르게 쓴다.
2. 렌더 → 실제 이미지 확인 → 수정 루프를 스스로 돌린다.
3. "여기만 고쳐"라고 하면 거기만 고친다.

원칙은 다음과 같다.

- native Figure/Axes를 유지한다. 새 DSL이나 `plot_<kind>` 래퍼는 만들지 않는다.
- 판정은 고정 평가셋과 결정적 검사로 한다. 리뷰어 합의나 VLM 점수는 보조로만 쓴다.
- 출력이 바뀌는 변경은 버그 수정뿐이다. 스타일 불변을 기준으로 하고, 사람이 전후 PoC를 확인한다.
- 에이전트가 읽는 문서는 짧고 단정적으로 쓴다. 공개 API·MCP·CLI·`asset/**` 경로는 추가만 한다.

## 단계

### 0. 평가셋과 판정 규칙 (외부 판정기)

- **평가셋**: 자연어 요청 40개로 구성한다.
  - 생성 25개, 편집 15개다.
  - 한/영과 논문·보고서·발표 용도를 섞는다.
  - 10개는 held-out으로 둔다. skill과 문서를 다듬을 때 이 10개는 보지 않는다.
- **러너**: wheel을 설치한 임시 프로젝트에서 `claude -p`와 `codex exec`를 헤드리스로 실행한다.
  - 기본 상한은 20 turns, 300 s다.
  - 에이전트 프로젝트에는 입력 파일(편집이면 base script까지)만 복사한다. oracle, 정답, 채점기는 에이전트가 볼 수 없는 곳에 둔다.
  - prompt 끝에 붙이는 문구는 설치된 라이브러리와 출력 경로만 알린다. 작업 방법은 가르치지 않는다.
- **판정 항목**: 다음을 따로 기록한다.
  - `execution_success`: 에이전트가 직접 실행해 만든 원본 PNG·PDF를 기준으로 판단한다. 채점기가 다시 실행한 결과는 별도로 남긴다.
  - `task_success`: execution_success에 값·요청·보존 검사 통과를 더한 것이다.
  - `inspection_observed`: 마지막 수정 이후에 에이전트가 최종 PNG를 실제로 열었는지를 도구 이벤트로 확인한다.
  - skill이 발견됐는지, 실제로 호출됐는지.
- **값 검사**: 다음을 비교한다.
  - 계열의 정체(라벨 → 데이터), 짝지은 좌표와 범주 대응, 관측 중복도, 순서, NaN mask.
  - 분포형과 집계형 그림은 따로 정의한 계약으로 비교한다.
  - 채점기 자체 시험으로, 라벨 뒤바꿈·좌표 순서 변경·관측 누락·gap 제거·관측 중복을 모두 거부해야 한다.
- **편집 검사**: 편집 요청은 `explicit`("축 라벨만")과 `broad`("더 보기 좋게")로 나눈다.
  - explicit은 대상이 아닌 속성이 모두 그대로여야 한다. 대상: 좌표, mask, scale, spine, 역할별 글자, 계열 스타일, 위치, 범례, 크기.
  - broad는 데이터 보존만 필수이고, 나머지 변화는 보고만 한다.
- **실험 설계**:
  - A/B는 같은 wheel hash에서 skill이 없을 때와 있을 때를 비교한다. model, effort, 권한, 호스트 설정을 기록하고 실행 순서는 무작위로 짝짓는다.
  - 파일럿은 4사례 × 2호스트 × 2조건 = 16회다.
  - 결정 실험은 40사례 × 2반복 × 2호스트 × 2조건 = 320회다. 후보마다 한 번만 돌리고, 파일럿에서 잰 사용량으로 비용을 먼저 추정한다.
- **판정 규칙**: 호스트마다 다음을 본다.
  - task_success 차이가 10%p 이상이고, 사례 단위 bootstrap 95% 구간이 0보다 위에 있으면 "개선"이다. 아니면 "판단 보류"다.
  - tokens는 10% 비열등 범위를 본다.
  - 값 검사와 편집 보존 검사는 차이 비교가 아니라 반드시 통과해야 하는 조건이다.
- **통과**: 다음이 모두 되면 0단계를 통과한다.
  - 채점기 변이 시험이 통과한다.
  - 현재 main 기준선이 기록되고, 같은 명령으로 다시 재현된다.

### 1. 에이전트 진입

- **skill 위치**: wheel에 skill을 동봉한다. 위치는 `src/dartwork_mpl/skills/dartwork-mpl/`다.
- **router(SKILL.md)**: 에이전트가 자주 틀리는 것을 담는다.
  - 값과 NaN gap 보존
  - 대상만 수정
  - 저장한 PNG를 실제로 열어 보기
  - `CHECK_FAILED` 처리
  - 기하 레시피와 팔레트 목록은 references로 보낸다.
- **편집 레퍼런스(4단계에서 앞당김)**:
  - getter로 대상을 찾는다. 예: `get_title(loc=...)`, `get_lines()`, `properties()`.
  - 원본 스크립트는 보존하고 새 stem으로 저장한다.
  - explicit 요청과 broad 요청을 구분한다.
- **설치 명령**: `python -m dartwork_mpl.skills install [--claude] [--codex] [--copy]`
  - 기본은 symlink다. `--copy`는 커밋해 둘 사본이 필요할 때 쓴다.
  - 사본의 파일 hash를 기록한다. 사용자가 고친 사본은 `--force` 없이 덮지 않는다.
  - 교체는 임시 위치에 먼저 준비한 뒤 바꿔 끼운다. 그래서 실패해도 기존 설치가 남는다.
- **소비자 진입 문서**: 60줄 이하로 쓴다. `asset/agent/AGENTS.md`와 `CLAUDE.md` 두 경로에 같은 문구를 싣는다.
- **문서와 runtime의 불일치 수정**:
  - aspect token 개수와 preset 개수가 문서와 다르다. runtime 값과 대조하는 테스트를 둔다.
  - `.cursor/rules`가 제거된 API를 쓴다.
  - "Be specific" 안내가 실제 사용법과 맞지 않는다.
  - 패널 라벨 레시피가 라벨을 이중으로 찍는다.
- **입력 허용**: `dm.figsize(w, "16:9")` 같은 비율 문자열을 받는다. px 입력에 대한 힌트도 고친다.
- **`/dataviz`와의 관계**: 두 skill이 함께 발동할 때의 지침만 적는다. 호스트가 우선순위를 보장한다고 주장하지 않는다.
- **AGENTS.md index 주입기**는 만들지 않는다. 평가에서 발견 실패가 확인될 때만 짧은 opt-in pointer를 검토한다.
- **통과**: 0단계 판정 규칙으로 skill이 있을 때 "개선"이 나온다. 아울러 무관한 새 프로젝트에서 두 호스트 모두 skill 이름을 말하지 않는 요청으로 발견·호출·준수를 따로 확인한다.

### 2. 레이아웃 견고성 (스타일 불변)

- 왼쪽·오른쪽 제목을 측정에 넣는다. guard를 둔 adapter 하나로 처리하고, 공개 API `get_title(loc=...)`와 교차 확인한다.
- figure 텍스트는 역할을 먼저 본다(suptitle → 위, supxlabel → 아래, supylabel → 왼쪽).
  - 역할이 없는 일반 텍스트는 가장자리 띠 안에 있을 때만 규칙을 적용한다.
  - 그 밖의 경우는 기존 동작을 유지한다.
- twin 축은 공유·중복 장식만 겹침 검사에서 뺀다. 서로 다른 제목·라벨·주석은 계속 검사한다.
- Axes3D는 tight bbox로 측정한다. 카메라 각도를 바꾼 경우와 z-label이 있는 경우를 포함한다.
- 가장자리 글자 잘림은 조사만 한다. 기본 margin은 바꾸지 않는다.
- **통과**:
  - 고급 템플릿 18 × preset 3에서 레이아웃으로 풀 수 있는 제목은 100% 보인다.
  - 캔버스보다 큰 제목은 overflow 진단이 분명히 나오고, 축이 파괴적으로 줄어들지 않는다. xfail로 넘기지 않는다.
  - 기존 pixel baseline이 그대로이고, matplotlib 최소 지원 버전(3.10.1)에서도 시험이 통과한다.
  - 전후 PoC를 사용자가 확인한다.

### 3. 검토 루프 (얇게 시작)

- `dm.review(fig, stem)`은 기존 저장·검증을 감싸는 얇은 wrapper로 시작한다.
  - 미완료 검사 상태를 명시한다.
  - 자동 수정은 하지 않는다.
  - 그림 요약(axes별 제목, 라벨, 계열, 범위, 범례, 캔버스 밖 텍스트)을 돌려준다.
- 잡음 경고는 표시할 때만 요약한다. 원본 findings는 보존한다.
- 스크립트를 실행하는 CLI는 평가에서 필요가 확인될 때까지 미룬다.
- 새 검사(제목 이탈, 범례 가림, 중복 텍스트, 가장자리 잘림)는 보정 fixture로 검증한다. 정상 그림 12개 이상과 일부러 망가뜨린 그림 12개 이상을 쓰고, twin, 밀집 차트, 반복 텍스트, 투명 범례를 포함한다.
- 오탐 0건은 이 fixture 집합에 대해서만 주장한다.

### 4. 편집 워크플로

- `dm.review(..., baseline=...)`은 의도를 판단하지 않는다.
  - 허용할 변경을 명시적으로 받거나, 중립적인 차이 목록만 돌려준다.
  - 그 차이가 요청된 변경인지는 에이전트가 해석한다.
- helper는 평가에서 반복 실패가 확인된 것만 PoC를 거쳐 추가한다.
- **통과**: explicit 편집 문항에서 대상이 아닌 속성의 보존률이 오르고, 반복 횟수가 준다.

### 5. 배포와 MCP (분리)

- skill과 검증된 수정은 준비되는 대로 릴리스한다. MCP 기본 노출을 줄이는 일은 MCP 계약 변경이므로 별도로 결정한다.

## 순서와 통합

- 0·1·2단계는 동시에 진행한다. 1·2단계는 0단계 기준선과 채점기 변이 시험이 끝난 뒤에 머지한다.
- 그 뒤 3 → 4 → 5 순서로 간다.
- 작업자는 격리된 브랜치에서 push까지만 한다. PR 생성과 머지는 결과물을 직접 검증한 뒤에 한다.

## ADR 0005 구조 리팩터와의 조율 (#518, #525–#528)

- **머지 순서**:
  1. 이미 열려 있는 core 스택 #525 → #526 → #527 → #528이 검사를 통과하면 먼저 머지한다.
  2. 그다음 1·2단계 변경을 통합 담당 한 명이 머지된 main 위로 한 번만 옮긴다.
- **기다리는 동안 할 일**: 회귀 fixture, PoC, 작은 패치를 준비한다. 스택 끝에서는 버리는 호환성 확인만 한다.
- **리팩터 담당에게 요청할 것**:
  - 이름 변경과 테스트 이동 대응표
  - 이 수정들이 들어갈 동안 L2·L3·U6을 잠시 비워 두기
- 서로 겹치지 않는 K/M/U 이동은 계속해도 된다. 기능 동결이 기계적 이동까지 막지는 않는다.

## 하지 않는 것

- 폰트, 굵기, 스파인, 격자, 프리셋 외관, 색 값과 색 순서는 바꾸지 않는다.
- 새 MCP 도구나 리소스, artifact 수명 확장, 호스팅 실행은 하지 않는다.
- 새 DSL, `plot_<kind>` 래퍼, 대형 AGENTS.md 주입기는 만들지 않는다.

## 전체 완료 판정

0단계 판정 규칙으로 Claude Code와 Codex 각각에서 다음 결과가 나오면 완료다. 결과는 같은 명령으로 재현돼야 한다.

- task_success가 "개선"으로 나온다.
- 값 검사와 편집 보존 검사를 통과한다.
- tokens가 비열등 범위 안에 있다.
