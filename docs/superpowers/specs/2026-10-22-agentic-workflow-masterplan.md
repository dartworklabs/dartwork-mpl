# 에이전트 워크플로 우선 전환 — 마스터 플랜

2026-10-22 · 기준 main `e8fe78a2` · 결정: 최원준 · 추적 #523 · 상위 로드맵 #482

## 결정

- **주 사용자**: Claude Code·Codex 같은 코딩 에이전트를 쓰는 사람. 그림을 자연어로 요청하고 자연어로 고친다.
- **우선순위**: 에이전트 워크플로 적합화가 외관 개선보다 먼저다. 기존 style(폰트·굵기·스파인·프리셋 외관)은 바꾸지 않는다.
  scientific의 왼쪽 스파인도 유지한다.
- **동결**: MCP 결과물 보존·리비전·입력 보관·삭제·데이터 수리의 신규 기능을 멈춘다. 지우지는 않는다.
  기존 도구와 계약, ADR 0003·0004의 잠금은 유지한다. 보안·데이터 손실 버그 수정은 계속한다.
- **보류**: #484(홈페이지·계정·커뮤니티·호스팅)와 #485(docs 분리). 0–3단계 지표가 기준선보다 나아진 뒤에 다시 판단한다.
- #483의 "새 공개 loader/CLI를 채택하지 않는다"는 범위 제한은 이 결정으로 바뀐다. 1단계 skill 설치 명령과 3단계 `dm.review`는
  기존 공개 이름을 건드리지 않고 추가만 한다.

## 북극성

dartwork-mpl을 처음 보는 프로젝트에서도 Claude Code·Codex가 다음 세 가지를 해낸다.

1. dartwork-mpl을 바로 올바르게 쓴다.
2. 렌더 → 확인 → 수정 루프를 스스로 돌린다.
3. "여기만 고쳐"라는 요청에 거기만 고친다.

## 원칙

- native Figure/Axes를 그대로 쓴다. 새 DSL이나 `plot_<kind>` 래퍼 계층은 만들지 않는다.
- 판정은 고정 평가셋과 결정적 검사로 한다. 리뷰어끼리의 합의나 VLM 점수는 보조 근거로만 쓴다.
- 출력 그림이 바뀌는 변경은 버그 수정만 한다. "스타일 불변"을 기준으로 두고 전후 PoC를 사람이 확인한 뒤 머지한다.
- 에이전트가 읽는 문서는 짧고 단정적으로 쓴다. 필수 지식은 약 1.5K tokens 이하로 둔다.
- 기존 공개 API·MCP·CLI 계약을 보존한다(ADR 0005 동결선과 같다). 바꾸지 않고 추가만 한다.

## 단계

### 0. 평가셋과 기준선

- 자연어 요청 40개를 만든다.
  - 생성 25개: line, bar, scatter, heatmap, 분포, 다중 패널, 이중축, 시계열 이벤트. 한국어와 영어, 논문·보고서·발표 용도를 섞는다.
  - 편집 15개: 축 라벨만 키우기, 패널 비율, 범례 위치, 한 계열 강조, 선 끝 라벨, "더 보기 좋게".
- fixture 데이터에는 값 oracle(행 수, 결측 위치, 그룹 합계)을 함께 둔다.
- 러너는 wheel을 설치한 임시 프로젝트에서 Claude Code(`claude -p`)와 Codex(`codex exec`)를 헤드리스로 실행한다.
  PNG, 소스, 로그를 모으고 컨택트 시트를 만든다.
- 지표는 다음과 같다. 미적 점수는 통과 기준에 넣지 않는다.
  - 무수정 성공률, 반복 횟수, tokens, 시간
  - 결정적 결함: 캔버스 밖 텍스트, 겹침, 잘림, 범례 가림
  - 값 fidelity
  - 편집할 때 대상이 아닌 속성이 보존되는지
- 위치는 `evals/agentic/`다. 패키지에 넣지 않고 기본 CI job에서도 뺀다. 수동으로 실행한다.
- **통과**: 현재 main의 기준선이 기록되고, 같은 명령 하나로 다시 돌릴 수 있다.

### 1. 에이전트 진입

- wheel에 skill을 동봉한다: `src/dartwork_mpl/skills/dartwork-mpl/SKILL.md`. 본문은 120줄 이하의 router로 쓰고,
  참조 파일을 붙인다(크기·레이아웃, 편집, 색, 한글, 검토 루프).
- 설치 명령을 만든다: `python -m dartwork_mpl.skills install [--claude] [--codex]`.
  `.claude/skills`와 `.agents/skills`에 연결하며, 패키지 버전과 함께 움직인다.
- 소비자 진입 문서는 60줄 이하로 쓴다. `dm.get_agent_doc("AGENTS")`가 기여자 규칙(ADR·색 동결)을 섞지 않게 한다.
- 문서와 runtime의 불일치를 고친다.
  - aspect token은 10개, preset은 7종인데 문서와 다르다.
  - 버전 표기가 0.4로 남아 있다.
  - `.cursor/rules`가 제거된 API를 쓴다.
  - "Be specific" 안내가 "더 보기 좋게"를 금지한다.
  - a/b/c 패널 라벨 레시피가 이중으로 찍힌다.
- skill 설명과 본문에 `/dataviz`와 함께 쓸 때의 규칙을 적는다(정적 출판 매체, 물리 크기, preset 우선).
- 입력을 너그럽게 받는다: `dm.figsize`에 `"16:9"` 같은 비율 문자열을 허용하고, `px` 입력에 대한 잘못된 힌트를 고친다.
- **통과**: 평가셋에서 skill이 있을 때 없을 때보다 무수정 성공률이 높고 token 사용이 적다. 소비자 진입 문서의 길이 상한을 테스트로 고정한다.

### 2. 레이아웃 견고성 (스타일 불변)

- `simple_layout`과 텍스트 검사가 `_left_title`·`_right_title`도 측정한다.
  대상: `layout.py:186,743`, `clipped_text.py`, `overflow.py`, `overlap.py`, `cross_axes.py`.
- figure 수준 텍스트(suptitle, `fig.text`)는 정렬과 y 위치를 보고 위·아래 여백에 배정한다(`layout.py:593-608`).
- twinx 쌍을 `CROSS_AXES_OVERLAP`에서 뺀다. Axes3D의 눈금은 바깥 여백 측정에서 뺀다(`layout.py:203-223`).
- `margin=0`일 때 가장자리 글자가 잘리는 문제(한글 제목 위쪽, 이중축 왼쪽 ylabel)는 측정 보정으로 해결한다. 기본 margin 값은 바꾸지 않는다.
- **통과**:
  - 고급 템플릿 18개 × preset 3개에서 제목 가시율 100%를 테스트로 고정한다.
  - 버그 사례를 뺀 기존 pixel baseline이 바뀌지 않는다.
  - 전후 PoC를 사용자가 확인한다.

### 3. 검토 루프

- `dm.review(fig, stem)` 하나로 다음을 한다.
  - PNG와 PDF를 저장한다.
  - findings를 돌려준다. 각 항목에 심각도와 dm 관용구로 쓴 수정 방법을 붙인다.
  - 그림 요약을 돌려준다: axes별 제목, 라벨, 계열 수, 데이터 범위, 범례, 캔버스 밖 텍스트.
- 같은 일을 하는 CLI를 둔다: `python -m dartwork_mpl.review plot.py`.
- 검사를 고친다.
  - 새로 잡을 것: 제목 이탈, 범례가 데이터를 가림, 중복 텍스트, 가장자리 잘림.
  - 과밀 tick 경고의 심각도를 올린다.
  - GRAYSCALE_SAFETY는 한 줄로 요약한다.
  - 메시지는 한 언어로 쓴다.
- **통과**: 진단 시험 그림 7개에 든 실제 결함 5종을 검출하고, twinx를 포함해 오탐이 0건이다.

### 4. 편집 워크플로

- `dm.review(..., baseline=이전 요약)`가 편집 전후의 요약을 비교해, 대상이 아닌 속성이 바뀌면 알린다.
- 대상을 찾는 레시피(라벨이나 패널로 artist 찾기)와 자주 쓰는 편집 레시피를 skill 참조 파일에 둔다.
- `title`·`highlight`·`label_lines` 같은 helper는 평가에서 반복 실패가 확인된 것만, PoC를 거쳐 추가한다.
- **통과**: 편집 15문항에서 대상이 아닌 속성의 보존률이 오르고 반복 횟수가 준다.

### 5. MCP 기본 노출 축소와 0.6.0 (별도 승인)

- MCP 기본 목록을 render·lint·색 조회로 줄이고 나머지를 opt-in으로 돌리는 일은 MCP 계약을 바꾸는 것이다. 그래서 따로 결정한다.
- 0.6.0 릴리스에는 skill과 설치 명령을 함께 싣는다.

## 순서와 병행

- 0단계와 1·2단계는 동시에 시작한다. 1·2단계는 0단계 기준선이 기록된 뒤에 머지한다.
- 그 뒤 3 → 4 → 5 순서로 간다.
- 각 단계의 작업자는 격리된 브랜치에서 push까지만 한다. PR 생성과 머지는 결과물을 직접 검증한 뒤에 한다.

## ADR 0005 구조 리팩터와의 조율 (#518)

- **겹치는 경로**:
  - 2·3단계: `layout.py`(C6), `validate/_checks`(L2–L3)
  - 1단계: `prompt`·`asset/prompt`(U6)
  - 동결 대상: `mcp/`(M1–M6), `ui/`(U1–U5)
- **제안 1**: M1–M6과 U1–U5의 우선순위를 동결 취지에 맞춰 뒤로 미룬다.
- **제안 2**: 같은 경로를 건드리는 PR을 동시에 열지 않는다(리팩터 진행 규칙 3과 같다).
  2·3단계 수정은 작게 쪼개 먼저 머지하고, 이동 PR이 그 뒤를 따르는 순서를 제안한다. 이동이 먼저 열려 있으면 그 PR이 머지될 때까지 기다린다.
- 최종 순서는 대표와 논의해 정한다.

## 하지 않는 것

- 폰트, 굵기, 스파인, 격자, 프리셋 외관, 색 값·순서를 바꾸지 않는다.
- 새 MCP 도구나 리소스, artifact 수명 확장, 호스팅 실행을 만들지 않는다.
- 새 DSL이나 `plot_<kind>` 래퍼를 만들지 않는다.

## 전체 완료 판정

다음이 모두 기준선보다 나아지고, 같은 명령으로 재현되면 완료다. 측정은 Claude Code와 Codex 양쪽에서 한다.

- 평가셋의 무수정 성공률
- 결정적 결함 수
- 편집할 때 대상이 아닌 속성의 보존률
- token 사용량
