# 색 시스템 교착 해소 설계

- 날짜: 2026-08-02
- 상태: Approved
- 범위: `refactor/oklab-color-system` 브랜치를 리뷰 가능한 상태로 되돌리는 절차
- 관련: [ADR 0001](../../adr/0001-oklab-centered-color-construction.md) ·
  [ADR 0002 (Rejected)](../../adr/0002-separate-shipped-color-compatibility-from-oklab-authoring.md)

## 1. 문제

OKLab/OKLCH 전환 작업이 리뷰 불가 상태로 멈췄다. 표면적 이유는 분량이지만,
실제 원인은 셋이다.

**리뷰 대상이 잘못 잡혀 있었다.** 언커밋 변경 128파일 +30,332/−22,183 중 사람이
판단할 코드는 `src/` 26파일 +2,304/−865뿐이고, 나머지는 SVG 재생성 약 38,000줄과
테스트 증가분이다. main 워크트리의 dirty 61파일은 전부 matplotlib
3.10.8→3.10.9 버전 문자열 때문에 재생성된 산출물로 실질 변경이 0이었다.

**종결 조건에 외부 판정기가 없었다.** "적대적 리뷰어 2인이 PASS할 때까지"를
종결 조건으로 삼으면, 같은 문서를 근거로 판정하는 리뷰어는 언제나 새 gap을
찾을 수 있어 루프가 수렴하지 않는다. 마지막 7시간의 산출물은 코드가 아니라
13,868줄 설계문서였고, 그 65%가 seccomp·`pivot_root`·`LD_AUDIT` 같은 색과
무관한 검증 메타였다.

**안전장치가 해제됐다.** ADR 0001은 "shipped hex를 바꾸지 않는다"를 완료
조건으로 명문화했는데, ADR 0002가 이를 "ADR 0001을 baseline이나 review evidence로
쓰지 않고" supersede하면서 그 잠금이 사라졌다.

## 2. 결정

작업을 **색을 바꾸는 것**과 **바꾸지 않는 것**으로 가르고, 그 경계에 기계
판정기를 놓는다. 사용자는 색이론을 배우지 않고 판정기의 pass/fail만 본다.

### 2.1 게이트 0 — 색 판정기

`tests/test_shipped_colors_hash.py`가 다섯 표면의 sha256을 각각 고정한다.

| 표면 | 행 수 |
|---|---|
| `named` — 등록 명명색 | 1,272 |
| `colormaps` — 컬러맵 × 256 스톱 | 99 |
| `presets` — 프리셋 prop_cycle + color rcParam | 588 |
| `discrete` — `dm.colors(name, n)` × family × n × reverse | 1,344 |
| `curated` — 손튜닝 팔레트 | 15 |

행 수를 digest와 별도로 고정해, 항목이 조용히 사라지면 불투명한 해시 불일치가
아니라 개수 불일치로 실패하게 한다. 범위를 벗어난 `n`은 예외 타입으로 기록해
각 family의 정의역 경계도 색과 함께 동결한다.

각 표면은 **개별 서브프로세스에서 측정한다.** 이 판정기가 답해야 할 질문은
"깨끗하게 import한 dartwork-mpl이 무슨 색을 출하하는가"이지 "테스트 세션 도중
무슨 색인가"가 아니다. 또한 표면끼리 독립이 아니다 — `presets`가 프리셋을
적용하면 로케일 의존 시맨틱 토큰 `dc.pos`/`dc.neg`가 전역 명명색 매핑에서
재바인딩되고(`-kr`은 빨강=양/파랑=음), `mpl.rc_context`는 rcParams만 복원하고
그 매핑은 복원하지 않는다. 이는 올바른 제품 동작이므로 판정기가 이를 피해
측정한다.

**검증:** 다섯 표면 모두 심어놓은 1채널 변경을 검출하며, 별도 프로세스 간
결정론적이다.

### 2.2 트랙 분리

| 트랙 | 내용 | 색 변경 |
|---|---|---|
| 1 | ADR 0002 기각, 복원 불가 계약만 ADR 0001 부록으로 흡수 | 없음 |
| 2 | 문서 정직화 — 07-21 evidence-tier rewrite | 없음 |
| 3 | 무해 수정 + 배포 정리 | 없음 |
| 보류 | gamut 오차 #1/#2 실수정 | **있음** |

트랙 1~3은 게이트 0이 통과하는 한 안전하다. 보류 항목은 별도 제안과 눈 승인
없이는 착수하지 않는다.

### 2.3 gamut 오차는 고치지 않고 정직하게 서술한다

`_generate.gamut_max_chroma`는 chroma 0.04 프로브로 `L`을 얼린 뒤 최대 chroma를
찾으므로 참값 대비 −21.5% ~ +13.2% 벗어난다. `_cmaps.diverging_pair`만 gamut
캡이 없어 어두운 팔의 chroma가 조용히 깎인다. 둘 다 실제 결함이지만 고치면
diverging 11종이 최대 6 ΔEok 진해져 승인된 색이 바뀐다.

따라서 **코드는 그대로 두고 이름·docstring·주석을 실제 동작에 맞춘다.** 교체
금지 조항은 ADR 0001 부록 A2에 박았다. 이것이 07-21이 제안한 evidence-tier
rewrite의 정신과 같다 — 구현을 문서에 맞추는 대신 문서를 구현에 맞춘다.

## 3. 하지 않는 것

- 색이론 코어(sRGB 전달함수, OKLab M1/M2, CIEDE2000, CVD 모델)를 손대지 않는다.
  표준 대조 전수 검증 결과 전부 정확하다. CIEDE2000은 Sharma-Wu-Dalal(2005)
  34쌍 검증셋을 통과하고, CVD는 선형 RGB에서 적용된다.
- `_generated.py`의 팔레트 값을 재생성하지 않는다.
- 새 대형 설계문서를 쓰지 않는다.

## 4. 검증

1. 게이트 0이 main과 `refactor/oklab-color-system` 양쪽에서 통과한다.
2. 전체 테스트가 양쪽에서 통과한다.
3. `ruff check` · `ruff format --check` · `mypy`가 통과한다.

## 5. 재발 방지

`AGENTS.md`에 네 줄로 박는다.

1. 설계문서는 200줄을 넘기지 않는다. 넘으면 분할한다.
2. 적대적 리뷰는 외부 판정기가 있을 때만 쓴다. "리뷰어 N/N PASS"를 단독 종결
   조건으로 삼지 않는다.
3. ADR은 선행 ADR의 잠금을 해제할 수 없다. 해제는 별도 승인 사안이다.
4. 완료 조건에 이 저장소의 개발 환경에서 실행할 수 없는 것을 넣지 않는다.

## 6. 조사 중 정정한 것

- **baseline SHA는 긴급하지 않다.** `_BASELINE_COMMIT`은 `git rev-parse HEAD`와
  비교되지 않는 provenance 라벨이고, 실제 잠금은 `_PINNED_BASELINES`의 파일
  경로 + sha256이다(`_ssot.py:296-302`). main이 앞으로 나가도 깨지지 않는다.
- **진짜 긴급했던 것은 untracked였다.** ADR 0001, 07-14 스펙, v6 소스 6파일,
  테스트 14개가 커밋된 적이 없었다. `git clean -fd` 한 번이면 사라지는
  상태였다.
- 명명색은 1,272개, 컬러맵은 99개다(1,320/146이 아니다).
