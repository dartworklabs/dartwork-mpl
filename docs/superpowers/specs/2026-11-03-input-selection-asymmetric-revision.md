## Input choice and preservation

Native initial/current-file work reads authorized input bytes once, hashes and
copies those same bytes under a new user-owned project output revision outside
`datasets`, and loads data from those pinned bytes/path. Its small local receipt
shows logical name, previous/current choice, source, hash and snapshot location;
it is an example, not a public schema. Existing revisions are not overwritten.

Previous-data/style-only work verifies and reuses the previously consumed bytes.
Explicit current-file work pins newly read current bytes in a new revision and
retains earlier requested style edits. Missing/corrupt snapshots or unknown prior
input evidence require a relevant choice; there is no silent upstream fallback.
Equal hashes establish byte identity, not freshness, permission or full
reproducibility. Native local copies have no automatic MCP seven-day lifetime.
MCP keeps its operator-private storage/admission authority and explicit
Copy → Retained → Copy selection, independently owned child copies and receipts.

Shared immutable fixtures contain only v1/v2 CSV and metadata, with a frozen hash
manifest. Preparation is exclusive: a second preparation refuses without changing
any bytes. Each route has its own authorized mutable upstream; only the controller
replaces it. Prior source, input receipts/copies, reports and rendered outputs are
retained. No fixture reference PNG/PDF or original output was rewritten.
