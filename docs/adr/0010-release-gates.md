# ADR-0010: 사용자에게 닿는 문은 소유자 한 명이 연다

| | |
| --- | --- |
| **번호** | ADR-0010 |
| **상태** | Accepted (2026-11-26, 소유자 지시) |
| **결정일** | 2026-11-26 |
| **결정자** | 소유자(CTO) |
| **관계** | `develop`·`main`의 브랜치 보호를 ruleset으로 옮긴다. 허브 리포의 ADR-0015와 짝이다 |

## 맥락

대중 공개를 앞두고 사용자에게 닿는 변경(`main`, PyPI, 허브 production)을 최종 검토자가 허락할 때만 나가게 해야 한다. 그때까지 `main`은 CI만 통과하면 쓰기 권한자 누구나 병합할 수 있었고, 태그는 보호되지 않아 push하는 순간 PyPI에 올라갔다. 조직 소유자는 소유자와 공동창업자 둘이다. 소유자는 에이전트로만 일하고, 감독하는 에이전트는 소유자와 같은 계정을 쓴다.

## 결정

1. **최종 검토자는 소유자(`Sangwon91`)다.** 팀 `release-owners`에 소유자 한 명만 둔다.
2. **승인은 소유자의 명시적 지시다.** 에이전트는 같은 계정이라 기술적으로 구별되지 않는다. 그래서 "병합", "릴리스", "배포" 지시 없이 에이전트는 `main` 병합, 태그 push, 배포 승인을 하지 않는다. UI를 거치지 않고 에이전트가 소유자의 지시로 승인하는 것은 소유자의 승인이다.
3. **기술적 잠금은 1차 보호막이다.**
   - ruleset `release-gate`: `main`의 갱신을 막고 `release-owners`만 PR로 우회한다.
   - ruleset `version-tags`: `v*` 태그의 생성·변경·삭제를 막고 `release-owners`만 우회한다.
   - ruleset `quality-gate`: `develop`·`main`에 PR, CI(`lint`, `test`), force-push·삭제 금지. 우회 없음.
   - environment `pypi`: 필수 승인자 소유자, `v*` 태그에서만. `release.yml`의 배포 job이 이 environment를 쓰고 PyPI trusted publisher가 이 이름에 묶인다.
4. **공동창업자의 조직 소유자 권한은 그대로 둔다.** ruleset은 조직 소유자에게도 적용되므로 강등하지 않아도 문이 막힌다. 조직 소유자는 ruleset을 고칠 수 있지만 감사 로그에 남는다.

## Trade-off

**장점:** 소유자 말고는 누구도 사용자에게 닿는 변경을 낼 수 없다. 소유자도 CI를 건너뛸 수 없다.

**비용:** 모든 릴리스가 소유자 한 명을 기다린다. 소유자가 없으면 긴급 수정도 멈춘다. 에이전트와 소유자가 같은 계정이라 에이전트의 실수는 설정이 막지 못하고 지시 규칙이 막는다.

## 검토하고 버린 것

- **에이전트 전용 계정.** 소유자가 에이전트를 자신과 같은 권한으로 본다.
- **공동창업자를 조직 구성원으로 강등.** 관계에 비해 과하다. ruleset으로 같은 효과를 낸다.
- **필수 리뷰어 1명.** 자기 PR은 승인할 수 없어 소유자의 PR이 막힌다.
