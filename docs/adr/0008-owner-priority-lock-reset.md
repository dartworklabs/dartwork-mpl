# ADR-0008: 소유자 결정 우선과 기존 잠금 재설정

| | |
| --- | --- |
| **번호** | ADR-0008 |
| **상태** | Accepted (2026-11-15, 소유자 승인) |
| **결정일** | 2026-11-15 |
| **결정자** | 소유자(CTO) |
| **대체** | 부분 대체: ADR 0005 결정 1(인터페이스 동결선) 중 미감 항목을 제외한 전부, ADR 0001 A1의 `mcp_discovery` 정확 일치 범위, ADR 0003의 닫힌 도구·템플릿 목록 |

## 맥락

소유자는 2026-11-15에 여섯 단계 리팩터를 정했다. Handbook, 구조 정리, 문서 분리, 히스토리 정리, MCP 재설계, 허브 계약이다. 그 과정에서 기존 잠금이 나왔을 때 소유자는 "내가 이제 정하는 게 최우선"이라고 답했다.

기존 잠금은 다음과 같다.

- **ADR 0001 A1**: 색 동결과 MCP discovery 정확 일치.
- **ADR 0003**: 허용된 MCP artifact 도구·템플릿의 닫힌 목록.
- **ADR 0005 결정 1**: 공개 이름, 시그니처, MCP 이름·등록 순서·스키마, CLI, UI 경로, `asset/**` 경로, 출하 색 값.
- **사전등록된 eval 입력의 바이트 고정**(#602).

이 잠금들은 MCP 재설계(5단계)와 의미 없는 기능 제거를 막는다. 소유자는 별도로 "미감적인 것은 유지하지만 기타 기능은 의미 없으면 도려낼 수 있다"고 정했다.

`CLAUDE.md` 규칙 3은 ADR이 앞선 ADR의 잠금을 스스로 풀지 못하게 한다. 그래서 잠금 해제를 청사진 ADR(0009)의 한 조항으로 넣지 않고 이 ADR로 따로 둔다.

## 결정

1. **미감 잠금은 유지한다.** 출하 색 값(`tests/test_shipped_colors_hash.py`), 폰트, 글자 무게, spine, grid, preset 모양은 계속 잠근다. 바꾸려면 소유자가 before/after를 본 뒤 승인한다.
2. **나머지 인터페이스 잠금은 푼다.** 다음은 의미가 없으면 제거하거나 바꿀 수 있다. 제거하면 CHANGELOG와 제거 이름 registry에 기록한다.
   - 공개 이름과 시그니처
   - MCP 도구·리소스·프롬프트의 이름, 등록 순서, 스키마, artifact v1
   - CLI, UI 경로
   - `asset/**` 중 미감과 무관한 경로
   - 사전등록 eval 입력
3. **소유자 결정 우선.** 이후에도 소유자의 새 결정이 앞선 잠금보다 우선한다. 잠금을 푸는 결정은 매번 별도 ADR로 기록한다.

## Trade-off

**이익**:
- MCP 재설계와 표면 축소를 바로 시작할 수 있다.
- 미감이라는 가장 비싼 자산은 계속 기계로 지킨다.

**비용**:
- 0.x 사용자가 minor 릴리스에서 이름 제거를 만날 수 있다.
- MCP 클라이언트 설정이 깨질 수 있다.
- 과거 eval 결과와 앞으로의 결과를 직접 비교할 수 없게 된다.

## 대안

- **모든 잠금 유지**: 5단계 MCP 재설계를 기존 이름·순서 안에서만 하게 된다. 도구 18개를 줄이는 목표와 충돌한다.
- **잠금 전부 해제**: 픽셀·색 판정기가 사라져 구조 리팩터의 회귀를 잡을 수단이 없어진다.
- **단계별로 그때그때 해제 ADR 작성**: 기록은 세밀하다. 하지만 소유자가 이미 범위를 정했으므로 같은 결정을 여러 번 반복하게 된다.

## 결과

- 승인되면 Handbook `docs/handbook/architecture.md`의 "기능 제거 정책"이 현재 규칙이 된다.
- `tests/architecture/`와 MCP discovery 테스트 중 이름·순서 정확 일치를 강제하는 검사는 MCP 재설계 PR에서 새 계약에 맞춰 바꾼다.
- 색 해시와 픽셀 baseline 게이트는 그대로 남는다.
