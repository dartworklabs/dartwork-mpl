# ADR-0009: dartwork-mpl 청사진 결정

| | |
| --- | --- |
| **번호** | ADR-0009 |
| **상태** | Accepted (2026-11-15, 소유자 승인) |
| **결정일** | 2026-11-15 |
| **결정자** | 소유자(CTO) |
| **관계** | ADR 0005의 slice 구조를 이어받는다. 잠금 해제는 ADR 0008이 따로 다룬다 |

## 맥락

dartwork-mpl은 matplotlib 위의 출판 품질 유틸리티 층이다. 사람과 AI 에이전트가 함께 쓴다. 기존 코드가 있는 상태에서 Handbook을 처음 만들며 다음 사실을 코드에서 확인했다.

- **구조**: ADR 0005의 기능 slice 구조가 이미 적용돼 있다. `scripts/check_boundaries.py`의 `DEBT`가 비어 있다.
- **규모**: 패키지 Python은 약 14.2만 줄이다. 그중 4.7할이 slice 안의 테스트이고, 제품 코드는 약 7.5만 줄이다. 그 절반 가까이가 주변 장치다. 색 동결 검증 약 1.7만 줄, MCP 약 1.1만 줄, UI 약 6.5천 줄이다.
- **판정기**: 색 해시, 픽셀 baseline(RMS 0.5), 경계 검사, mypy strict가 있다.

소유자는 리팩터 여섯 단계를 정했다(`docs/handbook/architecture.md` "채택한 리팩터 목표").

## 결정 — 축별 채택과 이탈

1. **축 1·3: 기능 slice + slice 안의 functional core, imperative shell.** 기본 청사진을 따른다. matplotlib 객체는 상태를 바꾸므로 변경을 shell(측정·적용)에 가둔다. 결정은 순수 함수로 둔다. 여러 기능이 쓰는 `layout`, `formatting`, `validate`도 slice로 두고 표면으로만 쓴다. 공용 utils 층은 만들지 않는다.
2. **축 4: 합격 판정은 여러 층으로 하고, 미감 판정기가 우선한다.**
   - 색 해시와 픽셀 baseline이 구조 리팩터의 제1 판정기다.
   - 그 위에 경계 검사, ratchet, 전체 테스트, mypy를 둔다.
   - 미감은 유지한다. 미감과 무관한 기능은 의미가 없으면 제거할 수 있다.
3. **축 7: 정본은 코드와 테스트다. Handbook은 의도·불변식·게이트의 정본이다.** 공개 표면은 `__all__`이 정본이다. 색과 픽셀은 테스트 고정점이 정본이다. 정본 매체와 검수 진실원이 다르다. 색 정본은 생성 코드이고, 검수 진실원은 digest다.
4. **축 8: Handbook 구성.** 네 topic으로 둔다.
   - purpose
   - architecture(도메인 포함)
   - verification
   - change-flow(운영·릴리스·용어 포함)

   라이브러리는 서버를 운영하지 않으므로 운영 topic을 따로 두지 않는다.
5. **축 11: 시간축 호환은 semver 0.x.** 제거는 minor 릴리스에 싣는다. CHANGELOG와 제거 이름 registry로 안내한다.

축 2(도메인), 5, 6, 9, 10은 기본값과 다르지 않아 따로 정하지 않았다.

## Trade-off

**이익**:
- 결정 로직을 그림 없이 테스트할 수 있다.
- 리팩터 회귀를 사람 리뷰가 아니라 픽셀·해시로 잡는다.

**비용**:
- shell과 core를 나누는 데 함수와 데이터 타입이 늘어난다.
- matplotlib이 측정과 적용을 한 호출에서 함께 하는 곳(텍스트 extent 등)은 경계가 깔끔하지 않다.

## 대안

- **전면 함수형**(상태별 타입, 예외 없는 흐름 강제): matplotlib 객체 모델과 마찰이 크다. 사용자가 계속 matplotlib을 직접 쓰는 철학과도 맞지 않는다.
- **현재(ADR 0005) 그대로**: slice 경계는 지키지만 slice 안의 결정 로직이 figure 상태와 섞인 채로 남는다.
- **리팩터 중 픽셀 변화 허용**: 구조 변경과 시각 변경이 한 PR에 섞여 회귀 판정이 불가능해진다.

## 결과

- 구조 리팩터 PR은 픽셀·색 게이트 통과, 경계·ratchet 수치 비증가로 합격한다.
- functional core 분리를 강제하는 기계 검사는 아직 없다. 2단계 plan에서 `DECISIONS` 확장 같은 판정기를 먼저 만든다.
