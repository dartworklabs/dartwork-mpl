# Gallery thumbnail path handling — audit

Audit triggered by issue [#313 (D23 — gallery thumbnail paths)](https://github.com/dartworklabs/dartwork-mpl/issues/313).

The issue suspected that the absolute paths emitted by sphinx-gallery
(`/examples_gallery/01_styling_and_themes/images/thumb/sphx_glr_*.png`)
would break in subpath deployments (e.g.
`https://example.com/dartwork-mpl/`). This audit demonstrates that
**the suspicion was a false alarm** and explains why.

## Setup

- Source paths in `docs/examples_gallery/*/index.rst` (generated by
  sphinx-gallery + concatenated by
  [`docs/_ext/build_hooks.py::write_manual_indices`](https://github.com/dartworklabs/dartwork-mpl/blob/main/docs/_ext/build_hooks.py))
  look like:

  ```rst
  .. image:: /examples_gallery/01_styling_and_themes/images/thumb/sphx_glr_plot_dark_mode_thumb.png
  ```

- Final HTML at `docs/_build/html/examples_gallery/index.html`
  contains:

  ```html
  <img src="../_images/sphx_glr_plot_dark_mode_thumb.png" ...>
  ```

## Key insight

The leading `/` in a docutils `.. image::` directive is **not a URL
path** — it's docutils' "srcdir-absolute" notation, identical to
sphinx's `.. doc::` `/foo/bar` semantics. At build time, sphinx
resolves it to a build-relative URL based on the location of the
*output* HTML file, not based on the source directive. The output we
observe above (`../_images/sphx_glr_*.png`) is a fully relative URL
that respects whatever base path the docs are mounted at — including
subpaths.

Concretely:

| Deployment | Page URL | `<img src="..">` resolves to |
|---|---|---|
| Root mount | `https://example.com/examples_gallery/index.html` | `https://example.com/_images/sphx_glr_*.png` ✓ |
| Subpath mount | `https://example.com/dartwork-mpl/examples_gallery/index.html` | `https://example.com/dartwork-mpl/_images/sphx_glr_*.png` ✓ |

Both work because the browser resolves the relative URL against the
current document's URL. Sphinx never emits an absolute URL — only an
HTML-relative one.

## Verification commands

```bash
# Confirm that the source uses srcdir-absolute notation
grep -n 'image:: /examples_gallery' docs/examples_gallery/index.rst | head

# Confirm that the rendered HTML uses HTML-relative URLs
grep -o 'src="[^"]*sphx_glr[^"]*"' docs/_build/html/examples_gallery/index.html | head -3
# Expect: src="../_images/sphx_glr_*_thumb.png"  ← relative, subpath-safe
```

## Conclusion

`.. image:: /...` directives are **not** absolute URLs and **do not**
break under subpath mounts. The issue can be closed without code or
template changes.

## When to revisit

This audit becomes invalid if any of the following changes:

1. We start emitting `<img src="/...">` (HTML-absolute) anywhere in
   the docs tree. Search guard: `grep -rE 'src="/[^"/]' docs/_build/html`.
2. We replace sphinx's HTML writer with a custom one that emits
   absolute URLs.
3. We move thumbnails out of sphinx's image-handling pipeline (e.g.
   into `_static` with direct `<img>` tags in raw HTML).

Until then, no action needed.
