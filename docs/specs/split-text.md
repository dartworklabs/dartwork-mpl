# 열을 이루는 글자와 여러 배경에 걸친 글자 (#812, #810)

> **한눈에**
>
> 두 이슈의 공통 해법으로 본 "한 글자를 조각으로 나눠 그리기"는 절반만 맞다. #812는 조각이 맞다. 다만 조각의 위치를 잰 폭으로 이어 붙이지 않고, 맞아야 할 두 조각이 한 앵커를 나눠 갖게 한다. #810은 문자열을 쪼개면 안 된다. 배경 경계는 글자 사이가 아니라 글자를 가로지르기 때문이다. `Text` 하나를 그대로 두고 배경 도형마다 한 번씩 잘라 그리거나(잉크 나누기), 한 색 또는 halo로 끝낸다. 두 기능은 코드를 공유하지 않는다.

상태: 탐색(spike) 결과. 프로토타입은 `spike/split_text/`에 있고 구현할 때 지운다. 그림과 수치는 `uv run python -m spike.split_text.cases`와 `... .robust`, `... .partial`이 `evals/runs/review/split-text/`에 다시 만든다(커밋하지 않는다). 아래 수치는 matplotlib 3.11.2, macOS에서 잰 값이다.

## 문제

| | 지금 | 원인 |
| --- | --- | --- |
| #812 | 포레스트 플롯의 `"0.8 [-3.6, 5.2]"`가 행마다 한 문자열이라 소수점·괄호·부호가 세로로 맞지 않는다. `dm.check`는 아무것도 보고하지 않는다 | 열이 아니라 문자열을 정렬한다. `-`(0.29 em)는 숫자(0.55 em)의 절반 폭이다 |
| #810 | 주석이 흰 바탕에서 진한 막대로 넘어가면 일부가 안 보인다. 풍배도 장면은 잉크의 60 %가 3:1 미만인데 `dm.check`는 조용하다 | `TEXT_CONTRAST`가 상자 중심점 한 곳의 색과 비교한다 |

번들 폰트를 확인했다. 프리셋의 첫 글꼴인 Roboto(숫자 1136/2048)와 Paperlogy(600/900)는 숫자가 이미 고정폭이다. Inter와 Pretendard만 비례폭이고 `tnum`을 갖는다. 그래서 숫자를 한 자씩 놓는 일은 필요 없다. matplotlib 3.11의 `Text.set_fontfeatures(["tnum"])`은 쓰지 않는다. 그릴 때는 적용되는데(Inter 20 pt의 `1111`과 `8888` 잉크 폭 29.8/47.3 → 47.8/48.7 pt) `get_window_extent`는 적용 전 폭(32.6/49.9 pt)을 그대로 돌려줘서, 레이아웃과 `dm.check`가 틀린 상자를 본다.

## 조사한 것

**#810에서 문자열 쪼개기는 어디서도 유일한 최선이 아니었다.** 다섯 장면에 일곱 후보를 그려 봤다.

| 점 구름(반투명 산점도) | 변화 없음 | 변화 없음 | 변화 없음 | 해당 없음 | 좋음 | 좋음 |

| 세로 글자, 누적 막대 3단 | 실패 | 좋음 | 좋음 | **가장 좋음** | 무난 | 스티커처럼 보임 |
| 한국어 주석, 네이비 막대 | 실패 | '1'이 반만 보임 | '131억'의 1이 사라짐 | **가장 좋음** | 무난 | 읽힘, 무거움 |

- 배경 경계는 글자 사이에 오지 않는다. 풍배도에서는 비스듬히, 등고선에서는 글자를 따라 길게 지난다. 글자·단어 단위는 경계가 우연히 빈칸에 올 때만 통한다.
- 등고선 라벨은 띠 둘에 걸쳐도 라벨마다 한 색(검정 또는 흰색)이면 다 읽힌다. 이슈가 걱정한 "숫자 하나에 색 하나로는 안 된다"는 경우는 재현 장면에 없었다.
- 점 구름은 대비 문제가 아니다. 글자와 배경의 대비는 5.98:1인데 점의 가장자리가 글자를 끊는다. 대비 규칙으로는 잡히지 않는다.
- 프리셋의 검정 글자는 `dm.colors("dc.blue", n=4)`의 가장 진한 단계에서도 4.4:1이다. 실패는 컬러맵 끝단(`dc.blue` 1.8:1, `viridis` 1.4:1), 사용자가 정한 진한 색, 회색 글자에서 난다.

## 메커니즘

`"NW: 6.2% of hours"`를 네 단어로 나눠 한 `Text`와 비교했다(`dm.simple_layout` 뒤, 잉크 상자의 끝 위치 차이).

| 방법 | 회전 0 (dpi 100/200/300) | 회전 30° | `dm.check`가 읽는 글자 | 판정 |
| --- | --- | --- | --- | --- |
| dpi 100에서 잰 폭을 포인트 오프셋으로 | 0 / +1.08 / +0.72 pt | y +0.72 pt | 4개 | 기각: 값이 부른 때의 dpi에 달린다 |
| 힌팅 없는 폭을 포인트 오프셋으로 | 0 / +0.72 / +0.48 pt | y +0.36 pt | 4개 | #812에 채택(아래) |
| `Annotation` 사슬(`xycoords=앞 조각`) | 0 / 0 / 0 | y −21.6 pt | 4개 | 기각: 회전하면 무너진다 |
| `offsetbox` `HPacker`/`TextArea` | 기준선 +1.4~2.2 pt | 행을 돌릴 수 없다 | 0개 | 기각: check가 못 보고, 행의 y를 데이터에 묶지 못한다 |
| `Text` 하나를 조각마다 한 번씩 그리기 | 0 / +1.08 / +0.72 pt | y +0.72 pt | 1개 | #810에 채택 |

표의 1 pt 안팎은 조각의 오차가 아니다. Agg가 힌팅한 한 줄 글자 자체가 dpi마다 그만큼 움직인다(`"0.8 [−3.6, 5.2]"`의 폭이 dpi 100/200/300에서 41.8/44.3/42.0 pt, PDF에서 42.5 pt). 힌팅이 없는 PDF와 SVG에서는 조각과 한 `Text`의 차이가 0.051 pt와 0.000 pt다.

**#812: 앵커를 나눠 갖는 native `Annotation`.** 조각의 y는 행의 데이터 값, x는 Axes 변에서의 포인트 오프셋이다. 소수점에서 만나는 두 조각은 같은 오프셋을 갖고 앞 조각은 거기서 끝나게(`ha="right"`), 뒤 조각은 거기서 시작하게(`ha="left"`) 놓는다. 그래서 정렬에는 잰 폭이 들어가지 않는다. 열 사이의 간격만 폭으로 정하고, 그 폭은 PDF·SVG가 쓰는 힌팅 없는 값(`matplotlib.textpath`)이라 dpi와 무관하고 그리기 전에 알 수 있다. 세로는 `va="baseline"`에 숫자 높이의 절반을 내려 모든 조각이 한 기준선에 선다(`"["`는 숫자보다 0.13~0.5 pt 높아 `va="center"`로는 어긋난다).

**#810: 한 `Text`, 여러 번 그리기.** path effect 하나가 글자 윤곽을 받아, 배경 도형(막대, 부채꼴, 등고선 띠)의 경로를 클립으로 걸고 그 안에서만 다른 잉크로 다시 그린다. 배치는 matplotlib이 매번 한 번 하므로 조각이 어긋날 수 없고, 클립은 도형의 transform을 그릴 때마다 따라가므로 레이아웃·dpi·벡터 출력에서 그대로 맞는다. 색 결정에만 래스터 표본을 쓰고 경계는 도형의 경로다. 프로토타입에서 찾은 함정 둘:

- Agg는 마지막 클립 경로를 객체 id로 기억한다. 그릴 때마다 만든 경로는 앞의 것과 id가 같아져 첫 조각만 그려진다. 경로를 path effect가 들고 있어야 한다.
- 전체를 먼저 그리고 조각을 덧그리면 처음 색이 테두리로 남는다. 도형 밖은 도형들을 구멍으로 뚫은 경로로 클립해 잉크를 한 번만 칠한다(겹친 도형은 먼저 합쳐야 한다).

비용: path effect가 걸린 글자는 윤곽으로 그려진다. PDF에서 그 글자는 선택·검색이 안 되고, Agg에서는 힌팅이 빠져 61 pt 문자열이 dpi 200·300에서 1.44·0.96 pt 넓어진다. halo도 같은 비용을 낸다.

## 공개 표면

```python
dm.text_columns(ax, y, columns, *, side="right", align=None, header=None) -> list[Text]
dm.legible(texts) -> None          # Text 하나 또는 여럿, dm.simple_layout 뒤에
```

```python
# 1. 포레스트 플롯: 왼쪽에 이름과 연도, 오른쪽에 추정값
dm.text_columns(ax, ypos, [names, years], side="left", header=["Study", "Year"])
cells = [f"{e:.1f} [{lo:.1f}, {hi:.1f}]" for e, lo, hi in rows]
dm.text_columns(ax, ypos, [cells], header=["Effect [95% CI]"])
dm.simple_layout(fig)

# 2. 막대 옆 "값 (비율)"
dm.text_columns(ax, range(len(bars)), [[f"{v:,.1f} ({s:.1%})" for v, s in data]])

# 3. 등고선 숫자, 막대에 걸친 주석
labels = ax.clabel(cs, fmt="%.1f")
dm.simple_layout(fig)
dm.legible(labels)
```

`dm.text_columns`의 약속:

- `columns`는 열의 목록이고 열은 행마다 문자열 하나다. 모든 칸에 숫자가 같은 개수로 있는 열은 숫자마다 소수점에 맞추고(`"0.8 [-3.6, 5.2]"`는 셋 다), 그 밖의 열은 왼쪽에 맞춘다. `align`은 열마다 `"left"`, `"right"`, `"center"`, `"decimal"`로 바꾼다.
- 숫자를 닫는 글자(`,` `%)` `]`)는 그 숫자에 붙고, 여는 괄호도 숫자에 붙는다. 숫자의 `-`는 U+2212로 찍는다(눈금이 이미 그렇게 한다).
- 글자는 눈금 라벨의 크기와 색, 머리글은 축 이름의 크기·무게·색으로 Axes 위에 놓는다. 열 사이와 Axes까지는 1.5 em이다.
- 왼쪽에 놓으면 y 눈금 라벨 자리를 대신하므로 그 라벨을 끄고, `dartwork_mpl.labels` 로거에 한 줄로 알린다.
- 조각은 `ax.texts`에 든 native `Annotation`이라 사용자가 색과 무게를 바꿀 수 있다.

`dm.legible`은 글자마다 위에서부터 처음 맞는 것 하나를 한다.

1. 읽힌다(어느 반 em 구간도 잉크의 절반 이상이 3:1 미만이 아니다): 그대로 둔다.
2. 한 색이 모든 잉크에서 읽힌다(3:1 미만이 2 % 미만): 그 색으로 바꾼다.
3. 아래가 평평한 도형들이다: 도형마다 읽히는 잉크. 둘 다 4.5:1을 넘는 도형에서는 글자 전체에서 더 많이 읽히는 쪽을 골라 색이 덜 바뀌게 한다.
4. 그 밖(점 구름, 이미지): 글자색의 반대 극으로 0.1 em halo.

잉크는 셋 중에서만 고른다: 글자의 원래 색, 프리셋의 `text.color`, Axes의 바탕색. 새 색을 만들지 않으므로 출하 색은 움직이지 않는다. 한 일은 글자마다 한 줄로 알린다. 박스는 자동으로 고르지 않는다(데이터를 가린다).

## 코드 자리

| 무엇 | 어디 | 이유 |
| --- | --- | --- |
| 칸 문자열 파싱(`Cell`, 숫자와 사이 글자) | `labels/model.py` | 문자열은 여기서 한 번만 타입이 된다 |
| 열 배치(조각의 오프셋과 정렬) | `labels/column_layout.py` (순수, `DECISIONS`에 등록) | 폭을 받아 계획을 돌려주는 결정 |
| 폭 측정과 `Annotation` 생성 | `labels/columns.py` | shell |
| 칸의 기록(조각들이 한 칸이라는 사실) | `geometry` (`record_panel_letters`와 같은 방식) | `labels`가 쓰고 `check`가 읽는다 |
| 글자 뒤의 배경 읽기(잉크와 종이) | `geometry/backdrop.py` | `check`와 `labels` 두 slice가 쓴다 |
| 잉크 결정(단색·도형별·halo) | `labels/decide.py`, 엣지는 `labels/edges.py` | 순수. 대비는 `colorspace` |
| 도형별 잉크 path effect, `dm.legible` | `labels/inks.py`, `labels/legible.py` | shell |

`compose`를 거칠 것은 없다. 두 함수는 rcParams와 platform만 읽으므로 다른 slice가 필요 없고 루트가 `labels`에서 바로 내보낸다. `layout`은 바꾸지 않는다. 조각이 Axes의 tight box에 들어가므로 `dm.simple_layout` 뒤 조각과 캔버스 변 사이는 왼쪽 2.83 pt, 오른쪽 2.83~3.55 pt다(여백 1 mm = 2.83 pt).

`check`는 칸을 한 글자로 읽어야 한다. 지금은 포레스트 플롯의 33칸을 84개의 자유 글자로 읽고, 괄호를 따로 놓은 판에서는 `TEXT_CROWD` 14개와 `OVERLAP` 1개를 낸다(`'9' and '['`). 기록된 칸은 조각의 합친 상자와 원래 문자열로 한 `Text` 사실이 되고, 같은 표의 칸끼리는 `TEXT_CROWD`를 보지 않는다.

## 자동과 힌트 (철학 1절, 7절)

| 능력 | 떠올리는가 | 틀리면 보이는가 | 자리 |
| --- | --- | --- | --- |
| 열 정렬 | 아니오(이슈의 에이전트는 행마다 한 문자열을 썼다) | 아니오(`dm.check` 무반응) | 기능. 폭 측정, 소수점 분리, 부호 폭이 얽혀 길다(프로토타입 280줄) |
| 부분 저대비 찾기 | 아니오 | 아니오 | `dm.check` 규칙. 그려진 것을 재야 한다 |
| 한 색으로 고치기 | 발견이 있으면 예 | 예 | 배경색은 그려야 알 수 있어 `dm.legible` 안에 둔다 |
| 도형별 잉크 | 아니오 | — | 기능(`dm.legible` 안). 클립 캐시와 테두리 함정이 있다 |
| halo | 반쯤(관용구) | 예 | `dm.legible` 안. 두 줄이지만 폭, 다크 프리셋의 색, 평평한 막대 위에서 무거움이 함정이다 |
| 박스 | 예(`bbox=`) | — | 두지 않는다. skill에 한 줄 |

`dm.simple_layout`은 `dm.legible`을 부르지 않는다. 글자색은 사용자가 정한 것이고, 놓친 자리는 `dm.check`가 알려주면 된다. 자동인 것은 왼쪽 열이 눈금 라벨을 끄는 일 하나이고 그것은 보고한다.

## `dm.check` 규칙

`TEXT_CONTRAST`의 측정을 바꾼다. 이름과 3:1은 그대로다. 사용자가 Axes에 놓은 글자마다 잉크 픽셀 하나하나를 그 뒤의 색과 비교하고, 글자 방향으로 반 em 구간을 나눠 한 구간이라도 잉크의 절반 이상이 3:1 미만이면 보고한다. halo와 글자 자신의 박스는 배경으로 친다.

```text
TEXT_CONTRAST: Axes[0]: 1 text(s) with ink under 3:1 on what is behind it, worst
'NW: 6.2% of hours': 60% of its ink, down to 1.76:1 on #020202
  try: move it onto one background; or dm.legible(text) picks the ink that
  reads on each (a halo over a point cloud)
```

`check`는 그림을 바꾸지 않는다. 프로토타입은 path effect를 잠깐 바꿨다 되돌리는데 구현에서는 허용되지 않는다. `geometry/renderer.py`의 그리지 않는 렌더러처럼, 글자의 잉크만 빼고 그리는 렌더러로 자기 캔버스에 그린다. 그림을 두 번 더 그리는 비용이 든다.

## 범위 밖

## 소유자가 정할 것

1. **머리글 무게.** 축 이름과 같게(프로토타입 기본, 그림 안의 무게가 늘지 않는다) 또는 굵게(이슈의 표현, `forest-bold.png`). 둘 다 보기 좋다.
2. **평평한 막대 위의 고침.** 도형별 잉크(또렷하다. 코드가 150줄쯤 늘고 그 글자는 윤곽이 된다) 또는 halo 하나로 끝내기(단순하다. 막대 위에서는 무겁다). 풍배도처럼 경계가 여럿이면 도형별 잉크도 색이 세 번 바뀐다.
3. **여는 괄호.** 숫자에 붙이기(기본) 또는 괄호를 한 열로(metafor 방식, `forest-fixed.png`). 뒤쪽은 짧은 숫자 앞에 빈 자리가 생긴다.
4. **3:1.** Light 무게의 작은 글자는 3.5:1에서도 흐리다(검정 글자와 `dc.blue9`). 4.5:1로 올리면 코퍼스에서 작동하는 그림이 5개에서 23개가 된다.
5. **함수 이름.** `dm.text_columns`와 `dm.legible`. 이슈의 제안은 `dm.text_table`과 `dm.ensure_legible`이다.
